# 转场 iOS 技术方案

首版使用 Swift 和 UIKit 原生开发，面向 iPhone，保留 iOS 14 起的兼容目标。本地任务库、本地作品存储和系统图片能力可以支撑已确定的轻量滚轮、创作、作品集和设置流程，首版不引入后台或第三方依赖。

本文是实现设计和验证计划。本次仅整理文档，没有完成业务代码、构建或真机测试。

## 分层与模块边界

采用轻量 MVVM。ViewController 与自定义 View 负责呈现和操作反馈；ViewModel 负责页面状态；服务负责任务规则、媒体处理和持久化。

建议模块如下：

| 模块 | 职责 |
| --- | --- |
| App | 生命周期、根导航和依赖装配 |
| DesignSystem | 颜色、字体、间距、按钮和通用状态视图 |
| Inspiration | 环境选择、滚轮、锁定和任务预览 |
| Themes | 主题列表和主题任务 |
| Creation | 拍摄、照片槽位、编辑与草稿 |
| Portfolio | 作品列表、系列与同题对照 |
| Settings | 偏好、存储和帮助 |
| Services | 任务规则、媒体、导出和存储 |
| Resources | 原创任务 JSON、插图与音效 |

模型和规则引擎不依赖视图实例，便于独立验证。各页面通过明确的模型 ID 和任务快照传递上下文。

## 滚轮组件

每列用循环展示的数据实现连续滚动的视觉效果，以固定高度单元和中心吸附保证结果清晰。有限内容通过重复索引映射展示，不创建无限数量的模型。上下使用渐隐遮罩，选中区域使用浅色背景。

状态分为 idle、spinning、settled。准备旋转时先生成有效结果，再计算目标位置和不同列的停止时间。动画只呈现结果，不负责决定任务。

锁定列保持原值；未锁定列可以按钮重转或手动调整。全部锁定时不触发旋转。快速连续点击不会产生多个并发结果。应用进入后台时停止动画并保存已确定结果；页面重新出现后重新同步真实位置。

减少动态效果开启时跳过长距离滚动。VoiceOver 可读出列名、选中值和锁定状态，并提供等价的调整操作。

## 任务规则

内置 JSON 至少包含 schemaVersion、内容版本、主题、任务模板、对象、方式、限制、环境标签、预计时长、步骤和素材槽位要求。使用稳定 ID 关联，展示文案可以更新。

每次生成按环境、时长、主题和锁定条件过滤有效任务，再按近期完成历史调整抽样权重。首版直接从有效任务候选中抽样，而不是独立抽三列后无限重试。

无候选时返回明确错误状态和可调整项，不静默清除锁定。不增加无法完成的新条件；手动选择与随机选择共用兼容规则。

为测试注入可替换的随机数来源，生产使用系统随机能力。启动内容检查需覆盖引用 ID、重复 ID、缺失步骤、版式照片数量和不存在的素材。

## 核心数据模型

| 模型 | 关键内容 |
| --- | --- |
| Theme | 稳定 ID、名称、说明、封面、任务列表 |
| TaskTemplate | 稳定 ID、内容版本、条件、环境、时长、步骤、版式 |
| TaskSnapshot | 任务 ID、版本、当次条件、文案、步骤与兼容上下文 |
| Draft | UUID、任务快照、槽位素材、配文、裁切参数、编辑时间 |
| Artwork | UUID、来源任务、快照、素材顺序、版式、配文、完成时间 |
| Series | 同题身份与关联作品，支持选取两次作品对照 |
| MediaAsset | UUID、相对路径、像素尺寸、方向、缩略图标识 |
| Preferences | 触感、音效和动态效果偏好 |

草稿和作品保存任务快照，以免内置任务库更新后历史内容失真。同题身份由稳定任务 ID 与规范化条件构成；再次创作创建独立 Draft，不覆盖旧 Artwork。

## 文件与数据库

Core Data 保存结构化元数据和图片相对路径。原素材放在 Application Support 的独立素材目录，缩略图放在 Caches。文件名使用 UUID，避免冲突。图片不以大块二进制反复存进数据库。

图片先写入临时位置，成功移动到素材目录后再提交引用。提交失败时回收未引用文件。文件系统与数据库没有跨系统事务，需要显式处理部分成功和恢复。

删除作品时先检查素材是否仍被草稿或其他作品引用，再删除不再使用的文件。清缓存仅移除可重建数据。素材丢失或空间不足时保留可恢复信息并显示错误，不把保存失败显示为成功。

草稿在素材变更、排序变更等明确操作后保存，文字编辑使用短延迟合并写入，并在离开页面时提交。不能只依赖进入后台才保存。

## 媒体与导出

相机使用独立捕获会话队列管理启动、停止和拍照，界面更新回到主线程。用户首次拍摄时申请相机权限；首版静态照片拍摄无需申请麦克风权限。

通过 PHPickerViewController 让用户按次选择图片，使用导入结果复制到应用目录，不依赖之后仍可访问原相册资源。处理导入中的取消、不可用资源和失败，避免留下空作品。[Apple 照片选择器文档](https://developer.apple.com/documentation/photosui/phpickerviewcontroller)

列表优先加载缩略图，大图使用 ImageIO 降采样。裁切参数单独保存，导出时按原素材与参数重新排版，避免多次压缩。确保处理旋转方向；成品默认不写入拍摄位置等非必要元数据。

分享与文件导出使用 UIActivityViewController。直接保存到相册是独立操作，届时请求对应添加权限。批量导出逐件处理，提供进度、取消和失败反馈，并清理临时文件。

首版成品导出为图片，不提供可恢复完整数据库的备份导入功能。

## 设置与系统集成

触感、音效和动态偏好用 UserDefaults 保存。跟随系统的动态效果监听系统减少动态效果状态；用户可以进一步减少应用动画。[Apple 动态效果文档](https://developer.apple.com/documentation/uikit/uiaccessibility/isreducemotionenabled)

存储占用从实际文件统计，不能使用原型中的固定数值。设置页不伪造系统权限开关，必要时提供前往系统设置入口。帮助与隐私正文可以本地阅读，正式发布所需的支持和隐私链接另行提供。

## 并发与兼容

UI 状态在主线程管理。图片读取、解码、导出和文件扫描放在合适的后台执行上下文；Core Data 使用自身 context 的 perform 机制。相机使用专用串行队列。

当前工程默认 MainActor 隔离，实施时应明确服务的执行边界，不能假设创建 Task 就自动转入后台。根据实际编译器能力处理隔离声明，并维持既有发布配置。

所有 API 使用都需检查 iOS 14 可用性。较新系统的便利 API 如用于实现，需提供兼容分支。最低版本兼容和最新系统运行均要验证。

## 验证计划

规则测试覆盖锁定保持、无候选、环境时长过滤、近期去重和历史快照。存储测试覆盖草稿恢复、文件写入失败和共享素材删除。避免只测试控件内部实现细节。

界面验证覆盖连续点击、后台中断、全锁定、手动滑动、较大字号、VoiceOver 与减少动态效果。媒体验证覆盖相机拒绝、导入取消、大尺寸照片、方向纠正、低存储和导出取消。

先完成适配范围内的构建与模拟器主流程，再用真机检查相机、触感、性能和系统权限。当前没有实际构建或测试通过的结论。
